## Команды

Зависимости ставим и обновляем **только через `pnpm`**. Ни `npm`, ни `yarn`: lock-файл в
репозитории один, и он `pnpm-lock.yaml`.

```bash
pnpm install --frozen-lockfile   # установка; в CI только так
pnpm run dev                     # разработка
pnpm run typecheck               # tsc --noEmit
pnpm run lint                    # eslint
pnpm run stylelint               # css
pnpm run format:check            # prettier
pnpm run test                    # vitest run
pnpm run build                   # tsc && vite build
pnpm api:check                   # контракт и типы совпадают с зафиксированным коммитом, он в develop бэкенда
pnpm api:sync [<sha>]            # контракт с головы develop бэкенда (или с <sha>) и типы из него
```

Node 22, версия зафиксирована в `.nvmrc`. Хуки включаются `pnpm install` (`core.hooksPath`
указывает на `.githooks`).

## Слои

Feature-Sliced Design: `app` → `pages` → `widgets` → `features` → `entities` → `shared`.

Импорт только сверху вниз: модуль не импортирует код более высокого слоя. `entities/diff` не
знает про `widgets/review-workspace`. Перекрёстный импорт внутри слоя — признак того, что общий
кусок должен уехать в `shared` или в `entities`.

Публичный вход у слайса один — его `index.ts`. Импорт из внутренностей чужого слайса запрещён.

## Состояние

| Категория                                                   | Инструмент        |
| ----------------------------------------------------------- | ----------------- |
| Серверные данные: прогоны, дифф, комментарии                | TanStack Query    |
| Общее состояние интерфейса: выбранный файл, фильтры, панели | Zustand           |
| Состояние одного компонента: hover, ввод, popover           | React local state |

Серверные данные не дублируются в Zustand: кэш живёт в Query, иначе появляются два источника
правды и рассинхрон. Глобальный store не заводится ради значения, которое нужно одному
компоненту.

Пока ручки нет на бэкенде (в контракте она с `x-not-implemented: true`), данные приходят через
mock adapter, типизированный по контракту, с той же границей, что и HTTP-клиент: компонент не
знает, откуда пришли данные.

## Типы

`any` не используется. Неизвестные данные на границе приходят как `unknown` и валидируются
перед употреблением. Доменные модели (`ReviewRun`, `DiffFile`, `DiffHunk`, `DiffLine`,
`ReviewFinding`, `PublishedComment`) описаны в архитектурном документе и живут в `entities`, а не в компоненте.

## Даты и числа

Даты, время и числа форматируются через `Intl` и общий форматтер из `shared/lib/format.ts`
(`formatDateTime`, `formatNumber`): один формат и один часовой пояс на всё приложение.
Библиотеки дат — `dayjs`, `moment`, `date-fns`, `luxon` — не подключаются; импорт запрещён
правилом `no-restricted-imports` в `eslint.config.mjs`. Нужен новый формат — новая функция
в `shared/lib/format.ts`, а не локальный `Intl.DateTimeFormat` в компоненте.

## Контракт API

Контракт первым: типы запросов и ответов API не пишутся руками, а генерируются
`openapi-typescript` из `docs/openapi/openapi.yaml` бэкенд-репозитория `dmc-268-api-t1`.

| Файл                                   | Что в нём                                                        |
| -------------------------------------- | ---------------------------------------------------------------- |
| `src/shared/api/contract/VERSION`      | sha коммита бэкенда, с которого взят контракт                    |
| `src/shared/api/contract/openapi.yaml` | контракт байт в байт как в бэкенде на этом коммите               |
| `src/shared/api/contract/schema.d.ts`  | типы `paths`, `components`, `operations` из `openapi-typescript` |

- Типы берутся оттуда: `import type { components, paths } from '@/shared/api/contract/schema'`.
  Слой `shared`, импортировать можно отовсюду.
- Тип ответа ручки, описанной в контракте, руками не пишется. zod-схема на границе остаётся —
  она проверяет данные во время работы, — но выводимый из неё тип должен совпадать с типом
  контракта, а не жить своей жизнью.
- Нужно поле или ручка, которой нет в контракте, — сначала PR в `openapi.yaml` бэкенда.
  Ручка, которую только планируют, описывается с `x-not-implemented: true`. После мёржа в
  `develop` бэкенда — `pnpm api:sync` (берёт голову `develop`) и PR во фронт с обновлёнными
  контрактом и типами.
- Фиксируется только коммит из `develop` бэкенда. Коммит из PR бэкенда (`pnpm api:sync <sha>`)
  допустим временно, пока фронт в работе: `pnpm api:check` его в мёрж не пропустит. Если в
  `develop` контракт новее зафиксированного, `api:check` предупреждает, но не падает.
- Моки отвечают по типам контракта: фикстура, которая не сходится с `components['schemas']`,
  — ошибка компиляции, а не повод поправить тип.
- `openapi.yaml`, `schema.d.ts` и `VERSION` руками не правятся. Prettier и ESLint их не трогают:
  `pnpm api:check` (он же job в CI) сравнивает их побайтно со скачанным контрактом и
  свежей генерацией и падает при расхождении.

## Тесты

Vitest и React Testing Library. Тест проверяет то, что видит пользователь: текст, роли,
состояние после действия. Селекторы по классам и по внутренним именам компонентов не
используются — они ломаются на рефакторинге, при котором поведение не менялось.

Подробности — скилл [`frontend-tdd`](../skills/frontend-tdd/SKILL.md).

## Стили

Tailwind CSS v4 отвечает за раскладку и локальное оформление. Ant Design — выбранный
визуальный UI-kit для интерактивных контролов; второй UI-kit не подключается. Повторяющаяся
композиция классов выносится в компонент `shared/ui`, а не копируется по слоям.
