# Ревью диффа

Две оси считаются параллельно и не сливаются: код может пройти одну и провалить другую.

Адаптировано из [`mattpocock/skills`](https://github.com/mattpocock/skills) (MIT),
`skills/engineering/code-review`.

## 1. Точка отсчёта

```bash
git rev-parse <база>            # по умолчанию develop
git diff <база>...HEAD          # три точки: против merge-base
git log <база>..HEAD --oneline
```

Пустой дифф или несуществующая ссылка — останавливаемся здесь.

## 2. Что доказывают инструменты

```bash
pnpm run typecheck && pnpm run lint && pnpm run stylelint && pnpm run format:check && pnpm run test
```

Замечания не повторяют их вывод: форматирование, порядок импортов, неиспользуемые переменные,
типы уже проверены. Это упавшая сборка, а не тема для комментария.

## 3. Ось Standards

Источники: [`AGENTS.md`](../../../AGENTS.md), [`rules/frontend.md`](../../rules/frontend.md),
`FRONTEND_ARCHITECTURE.md`.

Проверки поверх документов:

- импорт из более высокого слоя FSD или из внутренностей чужого слайса в обход `index.ts`;
- серверные данные продублированы в Zustand вместо TanStack Query;
- глобальный store ради значения, нужного одному компоненту;
- `any` или непроверенные данные с границы;
- доменная модель описана внутри компонента, а не в `entities`;
- компонент знает, откуда пришли данные: `fetch` или URL внутри UI-слоя;
- повторяющаяся композиция Tailwind-классов копируется вместо компонента в `shared/ui`;
- тест проверяет реализацию — класс, имя компонента, внутреннее состояние хука;
- поведение без теста: новая ветка условия в UI, которую никто не рендерит в тестах.

Запахи (Фаулер) — размеченные эвристики, не нарушения: Mysterious Name, Duplicated Code,
Feature Envy, Data Clumps, Primitive Obsession, Repeated Switches, Shotgun Surgery, Divergent
Change, Speculative Generality, Message Chains, Middle Man, Refused Bequest. Документированное
правило репозитория перебивает запах.

## 4. Ось Spec

Источник — артефакты OpenSpec-change (`openspec/changes/<name>/`) и задача:

```bash
gh pr view <n> --json body,title
gh issue view <n> --json title,body
```

Проверки: требование не реализовано или реализовано частично; в диффе есть поведение, которого
никто не просил; задача отмечена сделанной, а код её не закрывает. На каждое замечание — цитата
требования. Спеки нет — ось пропускается, и это указывается в отчёте.

## 5. Отчёт

Два раздела, `## Standards` и `## Spec`, findings между осями не переранжируются. В конце —
число находок по каждой оси и худшая внутри каждой.
