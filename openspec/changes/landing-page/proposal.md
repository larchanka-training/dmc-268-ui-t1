# Proposal

## Why

По адресу стенда сразу открывается SPA. Тот, кто зашёл впервые — ревьюер, комиссия на защите, — не видит, что это за сервис и как он устроен. Нужна страница о проекте до входа. Это должен быть готовый HTML: SPA отдаёт пустой `<div id="root">`, и текст с метаданными появляется только после выполнения JS. Поисковая выдача не цель — стенд на IP, проект учебный, — но разметка страницы должна быть правильной.

## What Changes

- Адреса делятся на два пространства: `/app/*` — SPA, всё остальное — статика. `/` — лендинг, несуществующий путь вне `/app/` получает статичную страницу 404, а не приложение.
- Лендинг — вторая HTML-точка входа в той же сборке Vite: разметка на Tailwind, без React и без JS приложения.
- Метаданные: `<title>`, `description`, canonical, Open Graph, `robots.txt`, `sitemap.xml`. Абсолютный адрес стенда подставляется при сборке образа.
- HTML приложения переезжает из `index.html` в `app/index.html`. Dev-сервер Vite отдаёт `/app/*` приложению так же, как nginx.
- Вход — статичная страница `/login` со ссылками на OAuth бэкенда; с cookie сессии — редирект на `/app/`. OAuth целиком на бэкенде, экран входа и callback из SPA (#16) уходят. Кнопка «Войти» на лендинге ведёт на `/login`.
- Проверки после деплоя: бандл для проверки gzip берётся из `/app/`, отдельно проверяются лендинг, глубокая ссылка в приложение и 404.
- Job `nginx` в CI, кроме `nginx -t`, поднимает образ и проверяет маршрутизацию.

## Capabilities

### New Capabilities

- `landing-page`: страница о проекте в корне стенда, готовым HTML с метаданными.

### Modified Capabilities

- `frontend-delivery`: адреса `/app/*` отдаются приложению, остальные — статике, с 404 для несуществующих.

## Impact

- Файлы: `index.html` (теперь лендинг), `app/index.html` (новый, HTML приложения), `vite.config.ts`, `src/landing/`, `public/`, `nginx/site.conf`, `Dockerfile`, `.github/workflows/ci.yml`, `.github/workflows/deploy.yml`.
- Адреса: приложение переезжает с `/` на `/app/`. Callback в OAuth-приложениях GitHub и GitLab прописывается с `/app` — это настройка у провайдеров, а не в коде.
- Порядок: ветка отведена от `feat/stand-http2-http3` (#22), где появились `site.conf`, gzip и проверки после деплоя. Маршруты роутера кабинета — в #16, префикс `/app` ставится там или следующим PR после его мерджа.
