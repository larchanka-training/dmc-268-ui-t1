## ADDED Requirements

### Requirement: Лендинг в корне — готовым HTML

Запрос `/` SHALL получать HTML лендинга, в котором текст страницы и метаданные есть в самом ответе сервера, без выполнения JS. Лендинг SHALL NOT загружать JS приложения. Лендинг SHALL содержать одну кнопку «Войти», ведущую на `/login`. Лендинг SHALL NOT определять наличие сессии.

#### Scenario: Страница без JS

- **WHEN** клиент запрашивает `/` с выключенным JS
- **THEN** он видит заголовок, описание сервиса и кнопку «Войти» на `/login`

#### Scenario: Нет бандла приложения

- **WHEN** клиент загружает `/`
- **THEN** в ответе нет `<div id="root">` и скриптов приложения

### Requirement: Страница входа — статика

`/login` SHALL отдавать статичную страницу входа без JS приложения, с входом через GitHub по ссылке на `/api/v1/auth/github/login`: OAuth целиком выполняет бэкенд. Запрос `/login` с cookie сессии SHALL перенаправляться на `/app/`. Наличие сессии SHALL определяться по наличию cookie, без запроса к API. Без JS вход SHALL работать.

#### Scenario: Гость открывает вход

- **WHEN** клиент без cookie сессии запрашивает `/login`
- **THEN** ответ — статичная страница с кнопкой «Войти через GitHub»

#### Scenario: Вошедший открывает вход

- **WHEN** клиент с cookie сессии запрашивает `/login`
- **THEN** ответ — редирект `302` на `/app/`

#### Scenario: Сессия протухла

- **WHEN** у клиента недействительная cookie сессии, и он перешёл на `/login`
- **THEN** его уводит в `/app/`, API отвечает `401` и удаляет cookie, приложение возвращает его на `/login`, и страница входа показывается

### Requirement: Страница входа передаёт `redirect` и показывает ошибку

Если `/login` открыта с параметром `redirect`, страница SHALL дописывать его к ссылкам входа, чтобы после входа бэкенд вернул пользователя на исходную страницу. Если `/login` открыта с параметром `error`, страница SHALL показывать понятное сообщение об ошибке входа. Скрипт, который это делает, SHALL NOT блокировать отрисовку страницы.

#### Scenario: Вход с глубокой ссылки

- **WHEN** гость открыл `/login?redirect=/app/reviews/42`
- **THEN** ссылка «Войти через GitHub» ведёт на `/api/v1/auth/github/login?redirect=/app/reviews/42`

#### Scenario: Отказ у провайдера

- **WHEN** пользователь вернулся на `/login?error=denied`
- **THEN** страница показывает, что вход отменён, и кнопки входа

#### Scenario: Без JS

- **WHEN** гость открыл `/login?redirect=/app/reviews/42` с выключенным JS
- **THEN** вход работает, после входа пользователь попадает на `/app/`

### Requirement: Метаданные лендинга

Лендинг SHALL содержать `<html lang="ru">`, `<title>`, `<meta name="description">`, `<link rel="canonical">` и Open Graph-разметку (`og:title`, `og:description`, `og:url`, `og:image`) с абсолютными адресами стенда. Корень сайта SHALL отдавать `robots.txt`, разрешающий `/` и закрывающий `/app/`, `/api/` и `/login`, и `sitemap.xml` с адресом лендинга.

#### Scenario: Превью ссылки

- **WHEN** ссылку на стенд вставляют в мессенджер
- **THEN** превью показывает заголовок, описание и картинку лендинга

#### Scenario: Адрес стенда в метаданных

- **WHEN** образ собран для стенда `https://62.169.24.237`
- **THEN** canonical, `og:url`, `og:image` и адрес в `sitemap.xml` начинаются с `https://62.169.24.237`

#### Scenario: Служебные пути закрыты для роботов

- **WHEN** робот запрашивает `/robots.txt`
- **THEN** в ответе `Disallow: /app/`, `Disallow: /api/`, `Disallow: /login` и строка `Sitemap` с абсолютным адресом
