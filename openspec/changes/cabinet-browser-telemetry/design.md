# Design

## Context

Бэкенд пишет трейсы OpenTelemetry (api#84), а входящий `traceparent` браузера принимает ссылкой, не родителем (api#110): серверный спан — корень своего трейса, `trace_id` из `X-Trace-ID` остаётся серверным. Коллектор, Tempo и Grafana — api#89, на проде api#108. Sentry не берём (api#89).

## Goals / Non-Goals

**Goals:** необработанные ошибки и запросы к API кабинета в Tempo; переход от спана запроса к трейсу API по ссылке и обратно по `X-Trace-ID`; ничего чувствительного в телеметрии; без адреса коллектора — ни байта наружу и ни байта SDK в загрузке.

**Non-Goals:** метрики браузера (Web Vitals), логи, действия пользователя, трассировка `EventSource` (заголовок `traceparent` к нему не добавить) — по запросу, отдельными изменениями. Показ `trace_id` в тексте ошибки на экране не меняется.

## Decisions

### Коллектор на том же адресе, что и интерфейс

`VITE_OTEL_EXPORTER_URL` — путь (`/otlp/v1/traces`), nginx интерфейса проксирует его на коллектор, как `/api/` на API (требование `frontend-delivery` «Браузер обращается к API по тому же адресу»). CSP `connect-src 'self'` не меняется, CORS в коллекторе не нужен, адрес коллектора не публикуется отдельно. Абсолютный адрес другого origin отвергается при старте: под текущим CSP браузер всё равно его заблокирует, а нарушение CSP в консоли — ошибка по требованию `frontend-delivery`.

Запрос экспортёра на тот же origin несёт cookie сессии: экспортёр шлёт его в режиме `same-origin`, настройки `credentials` у него нет (проверено в браузере). Прокси `/otlp/` в api#108 SHALL удалять `Cookie` (`proxy_set_header Cookie ""`) и ограничивать размер тела и частоту. Пока прокси нет, переменная не задаётся, и экспорт выключен.

Альтернатива — отдельный origin коллектора с CORS (так в тексте #49 и api#89): второй адрес в CSP, CORS в коллекторе, адрес в сборке — больше движущихся частей ради того же результата.

### SDK — отдельный чанк, загружается только при включённом экспорте

`shared/telemetry` в основном бандле — только `@opentelemetry/api` (без регистрации провайдера — no-op) и фильтр. SDK, экспортёр и инструментирование `fetch` — `import()` по условию: без адреса чанк не запрашивается. Ошибки до загрузки чанка копятся в очереди (не больше лимита) и уходят после.

С включённым экспортом первый рендер ждёт загрузки чанка (`main.tsx`): проверка в браузере показала, что без этого `GET /auth/me` и первые запросы экрана уходят раньше инструментирования `fetch` — без спана и `traceparent`. Цена — один запрос чанка (~21 КБ gzip, тот же адрес) до первого рендера и только при включённом экспорте; без адреса рендер не ждёт. Ожидание ограничено 2 с: телеметрия не должна держать кабинет пустым, если чанк завис; поздний SDK не увидит первые запросы.

### Пакеты — линия OpenTelemetry JS 3.0

`@opentelemetry/sdk-trace` 3.0 заменил `sdk-trace-base` и `sdk-trace-web` (у них 3.x нет, `sdk-trace-web` помечен «Use @opentelemetry/sdk-trace»). Вместе с ним — `api` 1.10, `core` и `resources` 3.0, `instrumentation*` и `exporter-trace-otlp-http` 0.300. `@opentelemetry/browser-sdk` (0.6) и `browser-instrumentation` (0.9) не берём: экспериментальные, на прошлой линии 2.x/0.2xx, ошибки отдают логами, а коллектору и Tempo в api#89 нужны спаны.

### Ошибки — спан `exception` с событием

Ошибка не привязана к запросу, поэтому — свой короткий спан со статусом ERROR и `recordException`. Источник — `app.error.source` (`window.error`, `unhandledrejection`, `react`). Ошибки React — через `onCaughtError`, `onUncaughtError` и `onRecoverableError` корня (`createRoot`): так видны и перехваченные `ErrorBoundary`, а сами границы ошибок не знают о телеметрии. Обработчики продолжают писать ошибку в консоль, как React по умолчанию.

### `X-Trace-ID` — одним атрибутом на обоих спанах

`app.api.trace_id` — на спане запроса (из заголовка ответа) и на спане ошибки (`ApiError.traceId`). Один поиск в Tempo находит и запрос, и ошибку. `ApiError` берёт `traceId` из `X-Trace-ID`, а без заголовка — из `trace_id` тела problem+json.

### Трассируются только запросы к API

Инструментирование `fetch` пропускает (`ignoreUrls`) всё, что не начинается с адреса API: без спана нет и `traceparent`. API на том же адресе, поэтому `traceparent` добавляется без настройки CORS. Экспортёр ходит исходным `fetch` с подавленной трассировкой — петли нет.

### Фильтр — в SDK, до экспорта

Сообщение и стектрейс фильтруются до `recordException`; `url.full` спанов `fetch` — процессором спанов в `onStart`, до любой отправки. Вход режется до регулярок (1000 символов сообщения, 1000 — строки стека): на длинной строке без пробелов разбор адресов квадратичен. Правила: строка запроса и фрагмент из адресов, `?ключ=…` и без пути; токены GitHub (`gh?_`, `github_pat_`), `Bearer …`, JWT, строки из 32+ символов `[A-Za-z0-9_-]` → `[скрыто]`; строки в кавычках длиннее 16 символов и обрезанные цитаты `"…"...` (так V8 показывает начало входа в ошибке `JSON.parse`) → `[скрыто]` (код из диффа и тексты замечаний попадают в сообщения именно цитатой, а имена свойств короткие); сообщение — первая строка, до 500 символов; стектрейс — без заголовка `имя: сообщение`, только строки кадров, до 50. Вторым рубежом редакцию делает коллектор (api#89).

## Risks / Trade-offs

- `@opentelemetry/instrumentation-fetch` в README помечен устаревшим: замена — `@opentelemetry/browser-instrumentation/experimental/fetch`. Она экспериментальная (0.9) и на прошлой линии 0.223 — с нашей 0.300 в бандле было бы две копии `instrumentation`. API почти тот же (`ignoreUrls`, `applyCustomAttributesOnSpan`, плюс `sanitizeUrl` вместо нашего процессора редакции `url.full`); переходим, когда она выйдет из experimental на текущей линии.

- Текст без кавычек (например, `detail` ответа API) фильтр не распознает как код. Бэкенд не кладёт пользовательские данные в `detail`; коллектор редактирует второй раз.
- Ошибки после выгрузки страницы теряются, если пакет не успел уйти; `BatchSpanProcessor` отправляет очередь при скрытии вкладки.
- SDK 3.0 вышел 20.10.2026; при регрессии — откат на 2.12/0.223: `sdk-trace-web` и `sdk-trace-base` вместо `sdk-trace`, импорты только в чанке SDK `shared/telemetry`.
