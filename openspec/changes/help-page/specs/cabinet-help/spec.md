# Spec Delta

## Purpose

Страница помощи: как подключить репозиторий и что делать, если что-то не работает.

## ADDED Requirements

### Requirement: Публичная страница помощи

Интерфейс SHALL отдавать страницу помощи по маршруту `/help` приложения (`/app/help`) без
проверки сессии и без запросов к серверу. Страница SHALL содержать разделы «Как начать» и
«Вопросы и ответы» на русском; текст SHALL храниться в коде фронта в одном месте.

#### Scenario: Гость открывает помощь

- **WHEN** пользователь без сессии открывает `/app/help`
- **THEN** страница показывает оба раздела
- **AND** интерфейс не делает запросов к API и не уводит на вход

### Requirement: Постоянные якоря вопросов

У «Как начать» и у каждого вопроса SHALL быть постоянный `id`-якорь: `start`, `repo-missing`,
`toggle-disabled`, `bot-silent`, `rerun`, `pause-review`, `remove-access`, `rules`,
`merge-gate`, `who-sees`. Якоря SHALL NOT меняться: на них ссылаются подсказки интерфейса.

#### Scenario: Переход по якорю

- **WHEN** пользователь открывает `/app/help#toggle-disabled`
- **THEN** страница прокручивается к вопросу «Почему переключатель «Ревью» неактивен?»

### Requirement: Пример правил ревью

Пример файла `.review/rules.md` SHALL показываться моноширинным блоком.

#### Scenario: Вопрос о правилах

- **WHEN** пользователь читает вопрос «Как задать свои правила ревью?»
- **THEN** пример файла выведен в `pre`/`code`

### Requirement: Ссылки на помощь

Боковое меню кабинета SHALL содержать пункт «Помощь», ведущий на `/help`. Страница входа
SHALL содержать ссылку «Как это работает?» на `/app/help`.

#### Scenario: Пункт меню

- **WHEN** пользователь выбирает «Помощь» в боковом меню
- **THEN** открывается страница помощи

#### Scenario: Страница входа

- **WHEN** гость открывает `/login`
- **THEN** на странице есть ссылка «Как это работает?» на `/app/help`
