## ADDED Requirements

### Requirement: Страница прогона

Интерфейс SHALL открывать прогон ревью по маршруту `/review-runs/:runId` и показывать название проверенного запроса на изменения, его автора, исходную и целевую ветки, его статус, коммит, способ запуска, время постановки, длительность, модель, потраченные токены и причину сбоя, если она есть. Если бэкенд вернул ссылку на change request, страница SHALL показывать её как внешнюю ссылку «Открыть источник» без названия провайдера. Ссылка SHALL показываться только для адресов `http` и `https`.

#### Scenario: Открытие завершённого прогона

- **WHEN** пользователь открывает `/review-runs/{run_id}` существующего прогона
- **THEN** страница показывает статус и метаданные прогона

#### Scenario: Вердикт и оценка

- **WHEN** прогон завершён и API вернул `verdict` и `score`
- **THEN** шапка показывает вердикт («Можно мёржить», «Есть замечания» или «Нужны правки») и оценку из 100

#### Scenario: Вердикта ещё нет

- **WHEN** прогон не завершён и `verdict` равен `null`
- **THEN** вместо вердикта показывается, что он появится после завершения

#### Scenario: Прогон не найден

- **WHEN** API отвечает `404` на запрос прогона
- **THEN** страница сообщает, что прогон не найден, и не предлагает повторить запрос

#### Scenario: Незнакомый статус

- **WHEN** API возвращает статус, которого нет в `ReviewRunStatus`
- **THEN** страница показывает его как есть и продолжает опрашивать прогон

### Requirement: Обновление активного прогона

Пока статус прогона нетерминальный, интерфейс SHALL опрашивать прогон и его замечания. После терминального статуса (`completed`, `failed`, `cancelled`) опрос SHALL прекращаться. О завершении прогона интерфейс SHALL судить только по статусу от сервера.

#### Scenario: Прогон завершается во время просмотра

- **WHEN** открыт прогон со статусом `analysing`, и сервер затем возвращает `completed`
- **THEN** статус на странице меняется без перезагрузки
- **AND** появляются замечания прогона
- **AND** дальнейших запросов прогона нет

### Requirement: Дифф выбранного файла

Интерфейс SHALL показывать список всех изменённых файлов прогона, включая файлы без замечаний, и дифф одного выбранного файла. Дифф SHALL отображаться в режиме «две колонки» или «одна колонка» с подсветкой синтаксиса и номерами строк старой и новой стороны. Выбранный режим SHALL сохраняться при переходе к другому файлу.

#### Scenario: Выбор файла

- **WHEN** пользователь выбирает файл в списке
- **THEN** показывается дифф только этого файла

#### Scenario: Смена режима

- **WHEN** пользователь включает режим «одна колонка» и выбирает другой файл
- **THEN** новый файл показывается в режиме «одна колонка»

#### Scenario: Нет базовой ревизии

- **WHEN** у прогона `base_sha` равен `null`
- **THEN** вместо диффа показывается объяснение, что дифф в момент ревью недоступен

#### Scenario: Бинарный файл

- **WHEN** выбран файл с `is_binary: true`
- **THEN** вместо построчного диффа показывается сообщение о бинарном файле

### Requirement: Inline-замечания

Замечание AI SHALL показываться раскрывающейся карточкой под строкой своей стороны диффа: `new_line` для `side: new`, `old_line` для `side: old`. Карточка SHALL показывать severity, категорию, текст замечания и то, опубликовано ли оно у провайдера. Если у замечания есть `suggestion`, карточка SHALL показывать блок предлагаемого кода: исходную строку и замену. Замечания `critical` и `high` SHALL быть раскрыты по умолчанию, остальные — свёрнуты.

#### Scenario: Замечание к добавленной строке

- **WHEN** у замечания `side: new` и `new_line: 23`
- **THEN** его карточка показывается под строкой 23 новой стороны

#### Scenario: Замечание к удалённой строке

- **WHEN** у замечания `side: old` и `old_line: 21`
- **THEN** его карточка показывается под строкой 21 старой стороны

#### Scenario: Замечание без привязки

- **WHEN** у замечания нет номера строки на его стороне
- **THEN** оно показывается в сводке прогона, а не в диффе

#### Scenario: Строка вне показанного диффа

- **WHEN** строка замечания не входит ни в один hunk файла
- **THEN** замечание показывается над диффом этого файла

### Requirement: Граница API

Ответы API SHALL проверяться схемой до попадания в компоненты. Ответ, не соответствующий контракту, SHALL показываться как ошибка загрузки, а не как частично заполненный экран.

#### Scenario: Ответ вне контракта

- **WHEN** API возвращает прогон без обязательных полей
- **THEN** страница показывает ошибку о несоответствии контракту
