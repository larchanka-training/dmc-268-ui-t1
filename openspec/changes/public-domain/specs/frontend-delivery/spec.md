## MODIFIED Requirements

### Requirement: Стенд отдаётся по HTTPS

Публичный адрес стенда SHALL отдавать интерфейс и API по HTTPS с сертификатом, который браузер принимает без предупреждений. Запрос по HTTP SHALL перенаправляться на HTTPS.

Сертификат SHALL выпускаться и продлеваться без участия человека и SHALL переживать повторное развёртывание: развёртывание SHALL NOT выпускать сертификат заново, если действующий ещё не истёк.

Публичный адрес стенда SHALL задаваться настройкой развёртывания — доменным именем или IP-адресом — без правки кода; без заданного имени SHALL использоваться IP-адрес сервера. На IP-адрес сертификат SHALL запрашиваться с профилем `shortlived`, на доменное имя — без профиля, со сроком, который ACME-сервер выдаёт по умолчанию. Сертификат от тестового ACME-сервера SHALL NOT оставаться на стенде после возврата на боевой.

#### Scenario: Открытие стенда по HTTP

- **WHEN** пользователь открывает адрес стенда по `http://`
- **THEN** он перенаправляется на `https://` и получает интерфейс без предупреждений о сертификате

#### Scenario: Повторное развёртывание

- **WHEN** развёртывание выполняется, пока действующий сертификат не истёк
- **THEN** используется сохранённый сертификат, и новый не запрашивается

#### Scenario: Стенд на IP-адресе

- **WHEN** доменное имя стенда не задано
- **THEN** стенд отдаётся по IP-адресу сервера с сертификатом профиля `shortlived`, как до появления домена

#### Scenario: Стенд на доменном имени

- **WHEN** задано доменное имя стенда, и его A-запись указывает на сервер
- **THEN** после развёртывания стенд отдаётся по этому имени с сертификатом профиля по умолчанию, и адрес в canonical, Open Graph и `sitemap.xml` — `https://` на это имя

#### Scenario: Возврат с тестового ACME-сервера

- **WHEN** стенд развёрнут с тестовым ACME-сервером, а затем развёртывание выполняется с боевым
- **THEN** стенд отдаёт сертификат боевого ACME-сервера, а не сохранённый сертификат тестового
