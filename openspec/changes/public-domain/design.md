# Design

## Профиль сертификата по виду адреса

Модуль `ngx_http_acme_module`: `profile name [require];` в `acme_issuer`, без директивы профиль не
запрашивается, и ACME-сервер выдаёт свой по умолчанию (у Let's Encrypt — `classic`, 90 дней).
`require` роняет заказ, если сервер профиль не поддерживает, — для IP это правильно: без
`shortlived` Let's Encrypt на IP не выдаёт ничего.

Вид адреса скрипт определяет без внешних утилит: только цифры и точки с тремя точками — IPv4,
остальное — имя хоста. IPv6 не поддерживается: в `server_name`, редиректе и адресе Grafana его
пришлось бы брать в скобки. `PUBLIC_HOST` с двоеточием скрипт отвергает, и контейнер не стартует. Имени верхнего уровня из одних цифр не бывает, поэтому
путаницы нет. Строка директивы целиком подставляется `envsubst` как `${ACME_PROFILE}`; для имени
хоста на её месте — комментарий, чтобы конфиг читался.

Альтернатива — отдельная переменная профиля в OpenTofu — отклонена: вид адреса уже однозначно
задаёт профиль, вторая переменная могла бы с ним разойтись.

## Состояние тестового каталога ACME

Файлы сертификатов модуль кладёт в `state_path` по имени идентификатора (`<домен>-<хеш>.crt`).
Что модуль сделает с сертификатом staging на томе после смены `uri` на боевой, документация не
говорит. Чтобы не проверять это на стенде, у каталога, отличного от боевого, — свой `state_path`:
`/var/lib/nginx-acme/test-directory` на том же томе. Боевой — `/var/lib/nginx-acme`, как раньше:
ключ аккаунта и сертификат на IP остаются на месте. Модуль создаёт подкаталог сам (проверено в
контейнере).

## Адрес стенда в деплое

`PUBLIC_HOST || VPS_DMC268_IP_T1` — выражение GitHub Actions: пустая или незаданная переменная
даёт IP. Origin сборки выводится из адреса (`https://<адрес>`), отдельной переменной не
заводим: расходиться им незачем. SSH (`stand-ssh`, `known_hosts`) остаётся на
`VPS_DMC268_IP_T1`: ключ хоста закреплён за IP.

## Staging и проверки после выката

Сертификату staging не доверяет ни blackbox, ни curl, и деплой с ним падал бы на проверке
публичного входа уже после apply. При заданном `ACME_DIRECTORY` job получает `TLS_INSECURE=1`:
`check-public.sh` дописывает модулям blackbox `tls_config.insecure_skip_verify: true` (во
временный файл), `check-routes.sh` и пробник `apply.sh` зовут `curl -k`. Остальные проверки —
HTTP/2, HTTP/3, заголовки, маршруты, API — идут как обычно. Предупреждение в логе шага
напоминает, что цепочка не сверялась.

## Проверки переменных

`service_host` (OpenTofu) — только имя хоста в нижнем регистре или IPv4: регулярное выражение по
меткам DNS, без схемы, пути, порта, точки в конце и заглавных букв. Значение идёт в конфиг nginx и
в адреса как есть, и ошибка в переменной ловится на `plan`, до изменений на сервере.

`acme_directory` не принимает боевой адрес Let's Encrypt (с косой чертой в конце и без): непустой
каталог считается тестовым — своё состояние на томе, проверки без сверки цепочки. Скрипт выбора
режима сравнивает адрес без косой черты в конце, так что и мимо OpenTofu боевой каталог не уходит
в `test-directory`.

## Тестовый каталог только ручным запуском

Job `gate` деплоя падает, если `ACME_DIRECTORY` задана, а запуск не ручной (`workflow_dispatch`),
и если в ней боевой адрес. Иначе забытая переменная катилась бы с каждым мержем, и проверки
публичного входа тихо не сверяли бы цепочку. Ручной запуск с тестовым каталогом пишет
предупреждение в summary.

## Origin кабинета и бэкенда

Бэкенд сверяет `Origin` изменяющих запросов со своим `PUBLIC_ORIGIN` побайтно, поэтому он ровно
`https://` + `PUBLIC_HOST`. `check-public.sh` после выката шлёт `POST /api/v1/auth/logout` с
`Origin: https://<HOST>`: без cookie ручка идемпотентна и отвечает 204, ничего не меняя.
`403 ORIGIN_FORBIDDEN` — ошибка деплоя; при `TLS_INSECURE` — предупреждение, потому что по
порядку перехода бэкенд переключается после первого выката на домен. Другие ответы (502 при
перезапуске API, сеть) — предупреждение: доступность API проверяет предыдущая проба.

## Перенаправление со старого адреса

`http://<IP>/` уже уходит на `https://<PUBLIC_HOST>/`: сервер на `:80` отвечает 301 при любом
`Host`, проверка HTTP-01 обслуживается модулем раньше location. `https://<IP>/` перенаправить
нельзя без сертификата на IP — это второй `acme_issuer` с `shortlived` и второй заказ;
не делаем, старый адрес по HTTPS после перехода показывает ошибку имени.
