## ADDED Requirements

### Requirement: Прогон по адресу

Экран прогона SHALL открываться по адресу `/reviews/{id}`, где `{id}` — идентификатор прогона на бэкенде, и SHALL загружать именно этот прогон. Если прогона с таким идентификатором нет, экран SHALL показывать «Прогон не найден» без кнопки повтора.

#### Scenario: Прогон из адреса

- **WHEN** пользователь открывает `/reviews/3f2a9c1e-5b7d-4e21-9a8f-0c6d2b1e4f70`
- **THEN** экран загружает и показывает прогон `3f2a9c1e-5b7d-4e21-9a8f-0c6d2b1e4f70`

#### Scenario: Неизвестный прогон

- **WHEN** пользователь открывает `/reviews/{id}`, а бэкенд отвечает `404`
- **THEN** экран показывает «Прогон не найден», и кнопки «Повторить» нет

### Requirement: Фильтр по файлам

Интерфейс SHALL позволять сузить список изменённых файлов по подстроке пути без учёта регистра и SHALL позволять показать только файлы, в которых есть замечания под текущие фильтры замечаний. Если выбранный файл выпал из списка, SHALL выбираться первый оставшийся файл.

#### Scenario: Поиск по пути

- **WHEN** пользователь вводит `api/` в фильтр файлов
- **THEN** в списке остаются только файлы, в пути которых есть `api/`

#### Scenario: Только файлы с замечаниями

- **WHEN** пользователь включает «Только с замечаниями» при фильтре severity `critical`
- **THEN** в списке остаются только файлы, где есть замечания `critical`

#### Scenario: Выбранный файл скрыт фильтром

- **WHEN** выбран файл, который перестал подходить под фильтр
- **THEN** выбирается первый файл отфильтрованного списка

### Requirement: Поиск по тексту замечаний

Интерфейс SHALL позволять искать замечания по подстроке в тексте замечания и в предлагаемом коде без учёта регистра. Пустая строка поиска SHALL показывать все замечания.

#### Scenario: Совпадение в тексте

- **WHEN** пользователь ищет `sql`, а у замечания текст «Возможна SQL-инъекция»
- **THEN** замечание остаётся в диффе, а замечания без совпадения скрыты

### Requirement: Сочетание фильтров

Фильтры разных видов SHALL применяться вместе: замечание показывается, только если подходит под все. Severity между собой SHALL объединяться через «или». Счётчики в списке файлов SHALL считать замечания под фильтры, сводка прогона — все замечания. Интерфейс SHALL показывать, сколько замечаний показано из общего числа, и SHALL давать сбросить все фильтры одним действием. Фильтры SHALL сохраняться при обновлении данных прогона.

#### Scenario: Severity и текст вместе

- **WHEN** выбраны severity `high` и `critical` и введён поиск `token`
- **THEN** показываются только замечания `high` или `critical`, в тексте которых есть `token`

#### Scenario: Ничего не найдено

- **WHEN** под фильтры не подходит ни один файл
- **THEN** вместо списка показывается сообщение и кнопка «Сбросить фильтры»

#### Scenario: Обновление прогона не сбрасывает фильтры

- **WHEN** фильтры заданы, и прогон перезапрошен после завершения
- **THEN** фильтры и выбранный файл остаются
