## Purpose

Технический экран позволяет проверить базовые UI-компоненты просмотра одного
mock-прогона ревью до появления browser-контракта backend API.

## ADDED Requirements

### Requirement: Просмотр mock-прогона ревью

Система SHALL отображать технический экран одного mock-прогона с его статусом,
списком файлов и данными, прошедшими валидацию на границе mock adapter.

#### Scenario: Корректные mock-данные

- **WHEN** пользователь открывает технический экран
- **THEN** система отображает статус прогона и список файлов из mock adapter

#### Scenario: Некорректные данные adapter

- **WHEN** mock adapter возвращает данные, не соответствующие UI-модели
- **THEN** система не передаёт эти данные компонентам просмотра и показывает безопасное сообщение об ошибке

### Requirement: Выбор файла и unified diff

Система SHALL позволять выбрать один файл из списка и отображать его diff в
unified-порядке без side-by-side режима.

#### Scenario: Выбор другого файла

- **WHEN** пользователь выбирает файл в списке
- **THEN** система отображает hunks выбранного файла, а прежний diff заменяется

#### Scenario: Содержимое hunk

- **WHEN** выбранный файл содержит hunk
- **THEN** система отображает removed, added и context-строки в исходном порядке с соответствующими номерами и визуальными отличиями

### Requirement: Inline-отображение замечаний

Система SHALL отображать `ReviewFinding` рядом только с изменённой строкой
соответствующей стороны diff.

#### Scenario: Finding новой строки

- **WHEN** finding указывает на added-строку через `side: 'new'` и `new_line`
- **THEN** система отображает его рядом с этой строкой

#### Scenario: Finding без подходящей строки

- **WHEN** finding не соответствует изменённой строке выбранного diff
- **THEN** система не прикрепляет его к произвольной context-строке

### Requirement: Доступное управление просмотром

Система SHALL делать выбор файла и фильтрацию замечаний доступными с клавиатуры
и предоставлять им понятные доступные имена.

#### Scenario: Управление с клавиатуры

- **WHEN** пользователь перемещается по интерфейсу с клавиатуры
- **THEN** он может выбрать файл и изменить фильтр без использования мыши

### Requirement: Mock-хронология прогона

Система SHALL отображать `RunInspector` с упорядоченной mock-хронологией
действий выбранного прогона без обращения к backend API.

#### Scenario: Выбор действия

- **WHEN** пользователь выбирает действие в хронологии
- **THEN** система отображает его статус, длительность и безопасный preview
