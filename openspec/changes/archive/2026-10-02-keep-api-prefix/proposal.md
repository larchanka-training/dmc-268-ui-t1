# Proposal

## Why

`nginx` в образе интерфейса срезает префикс `/api` перед тем, как передать запрос бэкенду: `GET /api/v1/reviews` приходит в приложение как `GET /v1/reviews`. Контракт API (`dmc-268-api-t1` #25) устроен наоборот: префикс `/api/v1` ставит само приложение, прокси его не трогает. Бэкенд (#36, #37) уже монтирует роутеры на `/api/v1/...`, фронт (#16) обращается к `/api/v1/...`. Со срезанием префикса каждая ручка API на стенде отдаёт 404.

Срезание держалось на одном потребителе — smoke-проверке деплоя, которая ходила на `/api/health`. Но `/health` не часть API: это проверка живости для Docker и деплоя бэкенда, она отвечает в корне приложения и ходит мимо `nginx`. Наружу через адрес интерфейса её публиковать незачем.

## What Changes

- `nginx` передаёт запрос под `/api/` бэкенду с исходным путём, без `rewrite`.
- `/health` через адрес интерфейса больше не публикуется.
- Smoke-проверка деплоя проверяет, что запрос под `/api/v1/` доходит до приложения: ответ должен прийти от API, а не от `nginx` и не от SPA-fallback.
- `infra/README.md` и `README.md` описывают путь без срезания.

## Capabilities

### Modified Capabilities

- `frontend-delivery`: требование о едином адресе дополняется тем, что путь запроса доходит до API без изменений.

## Impact

- `nginx.conf` — location `/api/`.
- `.github/workflows/deploy.yml` — шаг проверки API через адрес интерфейса.
- `infra/README.md`, `README.md` — описание проксирования.
- Бэкенд не меняется: он уже ждёт `/api/v1`, а `/health` остаётся в корне.
