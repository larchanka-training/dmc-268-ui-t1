## Why

Бэкенд проверяет видимость прогона через GitHub (dmc-268-api-t1#127): у `GET /api/v1/reviews/{review_run_id}`, `/steps` и `/diff` в контракте появился `502 SCM_UNAVAILABLE`. Экран прогона сам перезапрашивает прогон — при переподключении потока событий и на `run.finished`. Если такой перезапрос падал, уже загруженный прогон с находками сменялся ошибкой на весь экран. После `run.finished` поток уже закрыт, и итоговые замечания без ручного повтора не приходили.

## What Changes

- Контракт API — с `develop` бэкенда на `00a0b05` (`pnpm api:sync`).
- Ошибка на весь экран «Не удалось загрузить прогон» с повтором — только при первой загрузке.
- Упал перезапрос уже загруженного прогона — прогон остаётся на экране, сверху плашка «Не удалось обновить прогон» с «Повторить».
- Шаги или дифф не загрузились — прогон на экране без этой части.
