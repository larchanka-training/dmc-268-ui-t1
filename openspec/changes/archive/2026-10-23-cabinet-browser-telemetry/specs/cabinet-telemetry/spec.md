# Spec Delta

## Purpose

Описывает эксплуатационную телеметрию кабинета: какие ошибки и запросы браузер отправляет в коллектор OpenTelemetry команды, что в них не попадает никогда и при каком условии отправка включена. Телеметрия — для команды, пользователю она не показывается.

## ADDED Requirements

### Requirement: Экспорт включается адресом коллектора

Кабинет SHALL отправлять телеметрию только если при сборке задан адрес коллектора `VITE_OTEL_EXPORTER_URL`. Адрес SHALL быть путём на том же адресе, что и интерфейс. Без адреса или с адресом другого origin кабинет SHALL NOT загружать SDK телеметрии и SHALL NOT делать запросов к коллектору; запросы к API SHALL NOT получать `traceparent`.

#### Scenario: Адрес не задан

- **WHEN** кабинет собран без `VITE_OTEL_EXPORTER_URL` и на странице происходит ошибка
- **THEN** ни одного запроса к коллектору нет, запросы к API уходят без `traceparent`

#### Scenario: Адрес другого origin

- **WHEN** `VITE_OTEL_EXPORTER_URL` указывает на другой origin
- **THEN** экспорт выключен, в консоли — предупреждение

#### Scenario: Адрес задан

- **WHEN** кабинет собран с `VITE_OTEL_EXPORTER_URL=/otlp/v1/traces`
- **THEN** телеметрия уходит POST-запросами OTLP/HTTP на `/otlp/v1/traces` того же адреса

### Requirement: Необработанные ошибки отправляются

Необработанное исключение, необработанный отказ промиса и ошибка рендера React, в том числе перехваченная границей ошибок, SHALL отправляться спаном со статусом ERROR и событием `exception`: тип, сообщение и стектрейс после фильтра, путь страницы без строки запроса и источник ошибки. Для `ApiError` на спане SHALL быть `trace_id` API из `X-Trace-ID`.

#### Scenario: Ошибка рендера

- **WHEN** компонент бросает исключение при рендере
- **THEN** в коллектор уходит спан с событием `exception`, типом и стектрейсом ошибки и источником `react`

#### Scenario: Ошибка ответа API

- **WHEN** необработанной осталась `ApiError` ответа с `X-Trace-ID: 4bf92f3577b34da6a3ce929d0e0e4736`
- **THEN** у спана ошибки атрибут `app.api.trace_id` равен `4bf92f3577b34da6a3ce929d0e0e4736`

#### Scenario: Ошибка в первые миллисекунды

- **WHEN** ошибка случилась до того, как SDK загрузился
- **THEN** она отправляется после загрузки SDK

### Requirement: Число ошибок за загрузку страницы ограничено

Кабинет SHALL отправлять не больше 100 ошибок за одну загрузку страницы; остальные SHALL отбрасываться без запросов к коллектору.

#### Scenario: Ошибка в цикле

- **WHEN** ошибка повторяется тысячу раз за загрузку страницы
- **THEN** в коллектор уходит не больше 100 спанов ошибок

### Requirement: Запросы к API трассируются

Каждый запрос кабинета к API через `fetch` SHALL давать клиентский спан с методом, статусом ответа и адресом без строки запроса и SHALL нести заголовок `traceparent` этого спана. `X-Trace-ID` ответа SHALL записываться атрибутом `app.api.trace_id`. Запросы к другим адресам, в том числе к коллектору, SHALL NOT трассироваться и SHALL NOT получать `traceparent`. Поток событий (`EventSource`) не трассируется: заголовок к нему не добавить.

#### Scenario: Запрос к API

- **WHEN** кабинет запрашивает `/api/v1/reviews?repository_id=7`
- **THEN** запрос несёт `traceparent`, а у его спана `url.full` без `?repository_id=7` и `app.api.trace_id` из ответа

#### Scenario: Первые запросы страницы

- **WHEN** кабинет открывается и сразу запрашивает сессию и данные экрана
- **THEN** у этих запросов тоже есть спаны и `traceparent`

#### Scenario: Запрос не к API

- **WHEN** кабинет делает запрос не к API
- **THEN** спана нет и `traceparent` не добавляется

### Requirement: Чувствительное не покидает браузер

В сообщения, стектрейсы и атрибуты телеметрии SHALL NOT попадать строка запроса и фрагмент адреса, токены (GitHub, `Bearer`, JWT, длинные случайные строки), код из диффа и тексты замечаний. Фильтр SHALL вырезать строку запроса и фрагмент, заменять меткой токены, цитаты длиннее 16 символов и обрезанные цитаты и ограничивать длину сообщения и стектрейса; стектрейс SHALL NOT повторять сообщение. Cookie, заголовки и тела запросов SHALL NOT отправляться.

#### Scenario: Адрес с параметрами в сообщении

- **WHEN** сообщение ошибки содержит `https://host/api/v1/x?cursor=abc#frag`
- **THEN** отправляется `https://host/api/v1/x`

#### Scenario: Токен в сообщении

- **WHEN** сообщение содержит `ghp_` и 36 символов токена или `Bearer <токен>`
- **THEN** вместо токена — метка `[скрыто]`

#### Scenario: Код в сообщении

- **WHEN** `JSON.parse` упал на коде, и сообщение — `Unexpected token 'c', "const secr"... is not valid JSON`
- **THEN** вместо фрагмента — метка `[скрыто]`, короткие имена в кавычках (`'c'`, `reading 'map'`) остаются

#### Scenario: Многострочное сообщение

- **WHEN** сообщение ошибки многострочное, со строкой, похожей на кадр стека
- **THEN** уходит только первая строка, и в стектрейсе строк сообщения нет

### Requirement: Телеметрия описывает сборку

Каждый спан SHALL нести resource `service.name=dmc-268-ui`, `service.version` — sha коммита сборки и `deployment.environment.name` — окружение сборки.

#### Scenario: Спан со стенда

- **WHEN** спан пришёл от кабинета, собранного на коммите `abc1234` для окружения `production`
- **THEN** у него `service.name=dmc-268-ui`, `service.version=abc1234`, `deployment.environment.name=production`
