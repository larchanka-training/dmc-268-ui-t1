# Proposal

## Why

Стенд отдаётся по голому HTTP (`http://62.169.24.237`). Контракт API (`dmc-268-api-t1` #25, §9.1) ставит refresh-куке флаг `Secure`, а браузер не сохраняет такую куку с HTTP-адреса, если это не localhost: вход проходит, но после истечения access-токена пользователя выбрасывает. Кроме того, токены и кука идут по сети открытым текстом, а хостинг шлёт вебхуки на незащищённый адрес.

Домена у стенда нет и не будет. С января 2026 года Let's Encrypt выдаёт сертификаты на IP-адрес — только с профилем `shortlived`, сроком 160 часов. Такой сертификат возможен лишь при автоматическом продлении.

## What Changes

- TLS снимает сам `nginx` интерфейса — встроенным модулем `ngx_http_acme_module` (0.4.1), он уже есть в образе `nginx:1.30-alpine`. Модуль получает у Let's Encrypt сертификат на адрес стенда с профилем `shortlived`, продлевает его внутри процесса и подменяет без перезапуска. Второго контейнера и второго прокси нет.
- Режим выбирает переменная окружения `PUBLIC_HOST`. Задана — `nginx` слушает 443 с сертификатом на этот адрес, а 80 перенаправляет на HTTPS (запросы проверки ACME модуль обслуживает сам). Не задана — прежний HTTP на 80: так образ работает локально и в CI без обращения к Let's Encrypt. Выбор делает скрипт в `/docker-entrypoint.d/` при старте контейнера.
- Общие location (статика, `/api/`, SPA-fallback) вынесены в один файл и подключаются в оба режима, чтобы режимы не разошлись.
- Состояние модуля — ключ ACME-аккаунта и выпущенные сертификаты — лежит на томе `dmc268-ui-acme`, который переживает передеплой. Без этого каждый деплой выпускал бы сертификат заново и упирался в лимиты Let's Encrypt.
- Адрес ACME-сервера по умолчанию — боевой Let's Encrypt, переопределяется переменной `ACME_DIRECTORY` (staging, локальный Pebble для проверки).
- Smoke-проверки деплоя ходят на `https://` с проверкой сертификата: так деплой заодно убеждается, что сертификат действителен.

## Capabilities

### Modified Capabilities

- `frontend-delivery`: стенд отдаётся по HTTPS с действительным сертификатом, который продлевается без участия человека и переживает передеплой; сообщаемый адрес — `https://`.

## Impact

- `nginx.conf` разделён на `nginx/site.conf` (общие location), `nginx/http.conf` и `nginx/https.conf.template`; `Dockerfile` подключает модуль и скрипт выбора режима.
- `infra/main.tf`, `infra/variables.tf`, `infra/outputs.tf` — том состояния ACME, порт 443, переменная `public_tls`.
- `.github/workflows/deploy.yml` — переменные apply и smoke-проверки по HTTPS.
- `infra/README.md`, `README.md` — адрес стенда и устройство входа.
- Контракт API не меняется: `Secure`-кука на стенде начинает работать как написано.
