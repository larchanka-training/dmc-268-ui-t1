## Сверка требований с текущим состоянием (задача 1.2)

| Требование                                      | Состояние          | Причина                                                                                        |
| ----------------------------------------------- | ------------------ | ---------------------------------------------------------------------------------------------- |
| Статика собирается до развёртывания             | **не выполняется** | `docker_image "ui"` содержит блок `build` — при удалённом `docker_host` сборка уедет на сервер |
| Стек применяется после стека бэкенда            | выполняется        | `data "docker_network" "dmc268"` — сеть берётся готовой; отказ при её отсутствии внятный       |
| Единый origin для API                           | выполняется        | `nginx.conf` проксирует `/api/` на `dmc268-api:8000`                                           |
| Свежий `index.html` после развёртывания         | выполняется        | `no-cache` на `index.html`, `immutable` на `/assets/`                                          |
| Состояние вне исполнителя и отдельно от бэкенда | **не выполняется** | блока `backend` в конфигурации нет вовсе                                                       |
| Сообщаемый адрес пригоден для обращения         | **не выполняется** | `ui_url` собран из `bind_ip`, при `0.0.0.0` бесполезен                                         |

Три требования фиксируют уже достигнутое и защищают его от потери, три — цель для изменения про CD.
