# Proposal

## Why

Тест `ConnectRepositoryPage › подключает репозиторий и обновляет список подключённых` время от времени падает на CI: не находит заголовок «Репозитории» после подключения. Так было в ui#23 и ui#30 на коммитах, которые этого теста не касаются, а перезапуск проходил.

Причина — задержки моков API. После клика мутация ждёт `delay(500)`, затем `onSuccess` дожидается повторной загрузки доступных репозиториев (`delay(350)`), и только потом происходит переход на `/repositories`. Из 1000 мс, которые `findBy` ждёт по умолчанию, 850 уходят на моки. На медленном раннере оставшегося запаса не хватает на рендер двух страниц.

## What Changes

- В `src/pages/ConnectRepositoryPage.test.tsx` функции API подменяются на публичном входе слайса `@/entities/repository` через `vi.mock` с `importOriginal`: они отвечают сразу, а данные объявлены в самом тесте. Типы и остальной экспорт слайса остаются настоящими. Тест проверяет переход и обновление списка после подключения и от скорости раннера больше не зависит.
- Моки слайса (`mockStore`, `repositoryApi`) тест больше не задевает: подмена внутренних модулей слайса нарушала бы его публичный API (FSD), поэтому логику мок-слоя этот тест не проверяет.

## Impact

- Только тестовый файл. Код приложения, моки и требования спеки не меняются.
