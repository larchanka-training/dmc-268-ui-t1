## Context

Стек интерфейса — OpenTofu 1.13.2 с `kreuzwerker/docker` 4.6.0, демон Docker на сервере через `ssh://stand`. Контейнер `dmc268-ui` — `nginx:1.30-alpine` (`STOPSIGNAL SIGQUIT` в базовом образе), публичный вход и для интерфейса, и для API. Деплой передаёт образ ссылкой `имя:тег@digest`.

## Goals / Non-Goals

**Goals:** pull образа не попадает в простой публичного входа; остановка контейнера без SIGKILL; новый тег того же образа контейнер не пересоздаёт.

**Non-Goals:** выкат без простоя (второй контейнер и переключение трафика); снятие `registry_auth` с провайдера.

## Decisions

- **Контейнер ссылается на образ строкой, без `docker_image`** — как в бэкенде (api#204). Провайдер при создании контейнера (`findImage`) сначала ищет образ локально и тянет его, только если не нашёл; при чтении пишет в состояние `Config.Image`, то есть строку ссылки, поэтому вечного diff нет. Тег срезается регуляркой `local.ui_image_ref`, порт реестра тегом не считается.
- **Образ скачивает отдельный шаг до apply.** `docker pull --quiet` по `DOCKER_HOST=ssh://stand` после `docker/login-action`: docker CLI раннера отдаёт учётные данные демону вместе с запросом, на сервере токен не остаётся. Скачивание с тегом и digest кладёт образ под digest, и контейнер по ссылке без тега его находит — в репетиции во время apply событий `pull` нет.
- **`removed` с `destroy = false`.** У ресурса был `keep_locally = true`; `removed` убирает его из состояния без вызова провайдера.
- **`registry_auth` остаётся.** В деплое он не используется — образ уже на сервере, — но локальный `apply` без `docker pull` иначе не скачал бы приватный образ. Снимать его вместе с переменными — отдельной правкой после PR #90, который меняет те же строки `deploy.yml`.
- **`stop_signal = "SIGQUIT"`, `destroy_grace_seconds = 10`.** Без `destroy_grace_seconds` провайдер вызывает `ContainerStop` с таймаутом 0 — это и есть SIGKILL через миллисекунды. `stop_signal` совпадает с сигналом базового образа, атрибут вычисляемый, поэтому diff нет; явное значение не даёт смене базового образа молча вернуть быстрый выход по SIGTERM. `stop_timeout` не задан: он нужен только для `docker stop` и остановки демона, там по умолчанию 10 с, а `worker_shutdown_timeout` меньше.
- **Потоки SSE nginx обрывает через 1 с (`worker_shutdown_timeout 1s`).** По SIGQUIT nginx сразу закрывает слушающие сокеты и ждёт открытые: всё ожидание новые запросы получают отказ (ревью: с одним открытым потоком первый запрос после сигнала — `000`). В `nginx/site.conf` у `/api/` таймаутов прокси нет — действуют умолчания (`proxy_read_timeout 60s`), а API шлёт `event: ping` чаще, чем раз в 60 с, так что поток SSE таймаутом не закрывается и живёт часами. Ждать его целиком значило бы держать публичный вход закрытым до SIGKILL на каждом деплое, где открыта хотя бы одна вкладка кабинета. Ждать незачем: клиент сам переподключается через `retry: 3000` уже к новому контейнеру. Первым выбором было 5 с, как `--timeout-graceful-shutdown 5` у uvicorn, но это 5 с отказа почти на каждом деплое — столько же стоил pull, ради которого правка. 1 с хватает запросам к статике и `/api/`; доставка вебхука, оборванная посреди тела, вернётся повтором (воркер API повторяет неудачные доставки). Через 1 с воркер закрывает оставшиеся соединения и выходит сам, из цикла событий, а не посреди записи файла. 10 с grace — запас до SIGKILL на выход мастера.

## Репетиция

Отдельный `docker:29-dind` (Docker 29.9.2), OpenTofu 1.13.2 в `ghcr.io/opentofu/opentofu:1.13.2`, реестр `registry:2` в том же демоне, заглушка `dmc268-api` с потоком SSE (ping раз в 2 с), режим HTTP. Стек развёрнут конфигурацией с develop (`docker_image.ui`), затем — новой.

|                                                        | события Docker                                                                                         | итог                                                                |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| переход со старого состояния                           | `kill sig=3` → через 12 мс `kill sig=9`, `die exitCode=137`                                            | план `1 to add, 1 to destroy, 1 to forget`, pull во время apply нет |
| повторный plan, новый тег того же digest               | —                                                                                                      | `No changes`                                                        |
| новый digest, открыт поток SSE (замер при прежних 5 с) | `kill sig=3` → поток закрыт через 5,07 с → `die exitCode=0`; `start` нового через 5,34 с после сигнала | `Destruction complete after 5s`, SIGKILL нет                        |
| новый digest, без SSE                                  | `kill sig=3` → `die exitCode=0` через 0,14 с; `start` нового через 0,34 с                              | SIGKILL нет                                                         |

## Risks / Trade-offs

- Первый деплой после мёржа ещё с SIGKILL: удаление идёт по прежнему состоянию, где `destroy_grace_seconds` нет.
- При открытом потоке SSE простой публичного входа — ~1 с плюс запуск нового контейнера. Короче — обрываются обычные запросы; длиннее — отказ без пользы для SSE.
- HTTPS и QUIC в репетиции не проверялись: режим HTTP, без ACME. Конфиг HTTPS с `worker_shutdown_timeout` проверяет `nginx -t` в CI.
- `docker ps` на сервере показывает репозиторий без тега: что выкачено — в summary деплоя.
