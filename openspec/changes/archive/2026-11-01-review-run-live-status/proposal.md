# Proposal

## Why

Экран прогона из #18 показывает прогон таким, каким он был в момент загрузки. Пока worker собирает контекст, ходит в LLM и публикует замечания, пользователь видит застывший статус и узнаёт об окончании, только перезагрузив страницу. Задача спринта для Инженера 2 (#20): статус обновляется в реальном времени, видно, на каком этапе прогон, а замечания можно быстро отфильтровать по файлу, критичности и тексту. Definition of Done: статус обновляется без перезагрузки страницы, пользователь фильтрует замечания.

## What Changes

- Подписка экрана прогона на события статуса по SSE: нативный `EventSource` к `GET /api/v1/reviews/{id}/events`, пока прогон не завершён.
- Первое событие после каждого подключения — снимок текущего статуса. Поэтому пропущенное во время обрыва не теряется, и **polling не нужен** ни основным способом, ни запасным.
- События обновляют кэш прогона в TanStack Query. При переходе в терминальный статус экран один раз перезапрашивает прогон, чтобы получить замечания и вердикт, и закрывает подписку.
- `RunProgress` — пошаговый прогресс «Сбор контекста» → «Анализ LLM» → «Публикация» по статусам `building_context`, `analysing`, `publishing`, с отдельным видом для очереди, сбоя и отмены.
- Состояние соединения: при обрыве — плашка «Переподключаемся», данные на экране остаются; при отказе сервера — сообщение и кнопка «Обновить».
- Предупреждение о зависшем прогоне, если `last_progress_at` давно не менялся.
- Фильтры на экране диффа: по пути файла, «только файлы с замечаниями», текстовый поиск по замечаниям. Они сочетаются с уже существующим фильтром по severity и переживают обновления прогона.
- Mock-источник событий за тем же интерфейсом, что и `EventSource`: экран работает до готовности бэкенда.

**Не входит:** SSE-эндпоинт на бэкенде (Инженер 5), WebSocket, polling, уведомления вне открытого экрана прогона, сохранение фильтров в URL.

## Capabilities

### New Capabilities

- `review-run-live-status`: обновление статуса прогона в реальном времени по SSE, пошаговый прогресс, состояние соединения и предупреждение о зависшем прогоне.

### Modified Capabilities

- `review-run-view`: к фильтру по severity добавляются фильтр по файлам и текстовый поиск по замечаниям, задаётся их сочетание.

## Impact

- Код: `src/shared/api` (интерфейс источника событий), `src/entities/review-run` (схема события, подписка), `src/features/live-run-status` (новая), `src/features/filter-findings`, `src/widgets/review-run-view` (`RunProgress`), `src/widgets/review-workspace` (`FileList`), `src/pages/review-run`, `src/app/mocks`.
- Зависимости: новых нет. `EventSource` есть в браузере, `Steps` и `Alert` — в Ant Design.
- Бэкенду (Инженер 5): эндпоинт `GET /api/v1/reviews/{id}/events` по контракту из `design.md`, поля `last_progress_at` и `failed_stage` в событии.
- Инфраструктуре: прокси nginx на `/api/` не буферизует поток, если бэкенд отвечает `X-Accel-Buffering: no`. Иначе нужен отдельный `location` с `proxy_buffering off`.
- Порядок: change опирается на `review-run-diff-viewer` (PR #19) и архивируется после него — спеки `review-run-view` до этого в `openspec/specs/` нет.
