## Why

Фронтовая часть dmc-268-api-t1#88 (задача ui#50): блок «Ход прогона» на экране `/app/reviews/:reviewId` должен обновляться, пока прогон идёт. Перезапрос шагов на смене статуса уже есть в `ReviewRunView`, но без теста. Осталось два пункта задачи: `404` у шагов маскировался под «части нет», хотя `GET /steps` реализован (api#90); упавшая проверка замечаний у завершённого прогона (верификатор недоступен, fail-open) выглядела падением.

## What Changes

- Тест на перезапрос шагов по событию смены статуса — без таймеров.
- `404` у шагов — ошибка: на месте «Хода прогона» «Не удалось загрузить ход прогона» с «Повторить». Любая ошибка шагов, кроме `501`, теперь показывается так, а не прячет блок молча (требование «Ошибка загрузки части прогона» из `repositories-load-errors`/#62 уточняется для шагов). `501` по-прежнему скрывает блок. Дифф не меняется: он заглушка, `404` для него маскируется до api#87.
- Упавший `verifying` у прогона `completed` — «не перепроверено» с пояснением, без метки «ошибка» и кода.

## Capabilities

### Modified Capabilities

- `review-run-view`: ход прогона по событиям, ошибка загрузки шагов, непроверенные замечания.

## Impact

- Код: `src/pages/review-run/model/review.ts` (`usePlannedPart` — список статусов «части нет» у каждой части), `src/pages/review-run/ui/ReviewRunView.tsx`, `src/widgets/run-inspector/ui/RunInspector.tsx` (проп `runStatus`), тесты экрана.
- Контракт не меняется.
