# Proposal

## Why

Спека `frontend-delivery` описала контракт доставки, и сверка с текущим состоянием показала: три требования из шести не выполняются. Статика собирается локально из исходников — при развёртывании на сервер сборка уедет туда же, без контекста и кеша. Состояния развёртывания нет вообще: блока `backend` в конфигурации не существует, то есть из эфемерного исполнителя применять нечего. Сообщаемый адрес собран из интерфейса привязки и при публикации на все интерфейсы превращается в `http://0.0.0.0:8080`.

Практическое следствие простое: интерфейс не развёрнут и открыть его негде, притом что бэкенд на том же сервере работает и отвечает.

Вся необходимая машинерия уже существует и проверена на бэкенде: composite action, поднимающий хранилище состояния и открывающий к нему туннель, секреты доступа к серверу и к хранилищу заведены в этом репозитории, бакет создан.

## What Changes

- Образ интерфейса собирается в CI и публикуется в реестр с тегом по commit sha.
- `infra/` переходит с локальной сборки на получение готового тега; аутентификация в реестре — через `registry_auth` провайдера.
- Появляется состояние развёртывания в том же бакете, что у бэкенда, но под своим ключом: стеки независимы по состоянию.
- Сообщаемый адрес перестаёт собираться из интерфейса привязки — для клиентского имени хоста вводится отдельная переменная, как в бэкенде.
- Интерфейс публикуется на порт 80, поэтому адрес стенда не содержит номера порта.
- `required_version` поднимается до версии, которая проверяется.
- Появляется деплой-workflow на мерж в `develop`.

**Не входит:** схлопывание двух публичных входов в один. После этого изменения снаружи будут отвечать и API на 8000, и интерфейс на 80. Закрытие порта API требует изменения спеки `backend-delivery` в другом репозитории и должно идти одним шагом с ним.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет.

`skip_specs: true`: требования `frontend-delivery` не меняются — это изменение приводит реализацию в соответствие с тремя из них.

## Impact

- `infra/main.tf`, `infra/variables.tf`, `infra/outputs.tf`, `infra/versions.tf`, новый `infra/backend.tf`.
- Новый деплой-workflow и переиспользование composite action из репозитория бэкенда — его придётся продублировать здесь: GitHub не позволяет ссылаться на локальный action чужого репозитория.
- На сервере появляется контейнер интерфейса и публичный порт 80.
- Закрывает три требования спеки и основную часть задачи [#13](https://github.com/larchanka-training/dmc-268-ui-t1/issues/13).
