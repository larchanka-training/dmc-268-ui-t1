## Примечания к выполнению

**Два дефекта, которые нашлись только настоящим деплоем.**

1. **Сборка образа была сломана.** `pnpm install --frozen-lockfile` падал, потому что скрипт `prepare` выполняет `git config core.hooksPath`, а на этом слое образа есть только `package.json` и локфайлы. Похоже, образ интерфейса никогда не собирался в чистом контексте: в `infra/` стоял локальный `build`, и до реального деплоя дело не доходило. Скрипт сделан устойчивым к отсутствию git.

2. **Проксирование на API теряло путь.** Все запросы `/api/*` уходили на корневой эндпоинт: `proxy_pass` с переменной не заменяет префикс location, а берёт URI буквально, и там стоял просто `/`. Снаружи это выглядело успехом — 200 и JSON, только всегда один и тот же. Путь восстановлен `rewrite`; переменная оставлена, она нужна для старта nginx без резолва `dmc268-api`.

Второй дефект поймала именно строгая проверка: сначала она была написана как `curl | grep -q '"status"'`, и это дало ложный провал из-за `pipefail` (короткий `grep` закрывает канал, curl получает SIGPIPE). Убрав конвейер, стало видно настоящую причину — в теле не было `"status"`, потому что отвечал корень.

**Приёмка:** [прогон 36268631803](https://github.com/larchanka-training/dmc-268-ui-t1/actions/runs/36268631803) — интерфейс отдаётся, `/api/health` через его адрес возвращает `{"status":"ok"}`, повтор того же коммита даёт `No changes`. Снаружи проверено отдельно: главная, API через прокси и SPA-fallback на произвольном пути.
