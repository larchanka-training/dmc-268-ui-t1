# Proposal

## Why

Задача ui#123. Деплой develop падает на trivy по опубликованному образу: libexpat 2.9.0-r0 (CVE-2026-117610, исправлена в Alpine в 2.10.0-r0). CI на том же коммите зелёный: job `image` в `ci.yml` собирает `docker build` без кеша, и `apk upgrade` в стадии nginx (change `ci-image-checks`) ставит свежие пакеты. Деплой собирает build-push-action с кешем gha: строка `RUN apk upgrade` не меняется, слой приходит из кеша первой сборки — со старыми пакетами, и `apk upgrade` защищает только CI.

## What Changes

- `Dockerfile`: финальная стадия названа `runtime`.
- `deploy.yml`: `no-cache-filters: runtime` у build-push-action — стадия nginx с `apk upgrade` собирается заново на каждом деплое (секунды), стадия `build` (pnpm install, vite) по-прежнему из кеша gha.
- Комментарий у `provenance: false`: довод про одинаковый digest повторной сборки того же коммита больше не верен — runtime мимо кеша даёт новый digest на каждой сборке. Остаётся: аттестацию никто не читает, а с ней в ghcr уходит индекс с лишней записью вместо одного манифеста.

## Capabilities

Поведение интерфейса и стенда не меняется, спеки не правятся (`skip_specs`): сборка образа деплоя — та же, меняется только то, какие слои берутся из кеша.

## Impact

- `Dockerfile`, `.github/workflows/deploy.yml`.
- Перезапуск деплоя того же коммита теперь пересоздаёт контейнер интерфейса: digest новый. Деплой каждого нового коммита пересоздавал его и раньше.
