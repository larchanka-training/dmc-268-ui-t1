## Context

TLS на стенде снимает nginx интерфейса (`nginx:1.30-alpine`) с сертификатом от `ngx_http_acme_module`. Сертификат приходит через переменные `$acme_certificate` и `$acme_certificate_key`. Общие `location` лежат в `nginx/site.conf` и подключаются в оба режима. У `location = /index.html` и `location /assets/` свои `add_header Cache-Control`.

## Goals / Non-Goals

**Goals:**

- HTTP/2 для всех клиентов, которые приходят по TCP.
- HTTP/3 для клиентов, у которых проходит UDP 443, без потери доступности для остальных.
- Статика и ответы API уходят сжатыми; SSE — без сжатия и без задержек.
- Деплой падает, если стенд перестал отдавать HTTP/2 или HTTP/3.

**Non-Goals:**

- HTTP/2 и HTTP/3 в локальном режиме без TLS.
- 0-RTT (`ssl_early_data`): данные первого пакета можно повторить у сервера, а выигрыш — одна задержка до сервера на повторном заходе.
- Brotli — см. решение ниже.
- Настройка файрвола на VPS.

## Decisions

### HTTP/3 вместе с HTTP/2, а не вместо

Браузер не начинает с QUIC: первый запрос идёт по TCP, о HTTP/3 браузер узнаёт из `Alt-Svc` и пробует его на следующих запросах. Там, где UDP 443 закрыт (корпоративные сети, часть мобильных операторов), клиент остаётся на TCP. Без HTTP/2 он откатился бы на HTTP/1.1, и лимит в 6 соединений вернулся бы.

### `add_header_inherit merge`

`add_header` из `server` не наследуется в `location`, у которого есть свой `add_header`. Без этого `Alt-Svc` пропал бы как раз у `index.html` — первого ответа браузеру. Дублировать `Alt-Svc` в `site.conf` нельзя: файл общий с режимом без TLS. `add_header_inherit merge` (nginx 1.29.3+) на уровне `server` добавляет заголовки `server` к заголовкам `location`.

### `ma=86400`

Браузер помнит `Alt-Svc` сутки. Если UDP закроется, браузер сам вернётся на TCP после неудачной попытки QUIC, так что длинный срок ничего не ломает.

### gzip: статика заранее, API на лету

Статика неизменна между сборками, поэтому сжимается один раз в `Dockerfile` (`gzip -9 -k`), а nginx отдаёт готовый `.gz` через `gzip_static` без затрат CPU на запрос. Клиенту без `Accept-Encoding: gzip` уходит исходный файл. Ответы API сжимаются на лету (`gzip on`, `gzip_types` с `application/json`).

`text/event-stream` в `gzip_types` нет намеренно: сжатие буферизует ответ, и события SSE приходили бы пачками. `gzip_vary` добавляет `Vary: Accept-Encoding`, чтобы промежуточные кэши не отдали сжатый ответ клиенту, который его не просил.

Сжимать на лету и ответы API — компромисс с BREACH: атака требует секрета и отражённого ввода атакующего в одном сжатом ответе. Сессия живёт в httpOnly cookie, а не в теле ответа, поэтому риск принимаем.

### Brotli — не сейчас

На нашем бандле brotli `-q 11` даёт 59 КБ против 68 КБ у gzip `-9` — около 14%. Но в nginx его нет: ни в образе `nginx:1.30-alpine`, ни в репозитории пакетов nginx.org (там acme, njs, otel, geoip, image-filter, perl, xslt). Пакет из репозитория Alpine собран под другую сборку nginx и бинарно несовместим. Остаётся собирать `ngx_brotli` из исходников под точную версию nginx в отдельной стадии `Dockerfile` — ради ~9 КБ на первую загрузку, после которой `/assets/` и так кэшируется на год, это не окупается. Вернёмся, если nginx.org выпустит модуль.

### HSTS на сутки

`Strict-Transport-Security: max-age=86400` в HTTPS-сервере, с `always` и под `add_header_inherit merge`, как `Alt-Svc`, — иначе `index.html` и `/assets/` со своим `add_header` его теряют. Без HSTS первый заход по `http://` идёт открыто, и посредник может вместо редиректа на HTTPS отдать свою страницу (SSL stripping) — а с ней увести cookie сессии.

Срок — сутки, а не год. Браузер помнит заголовок весь `max-age`: если стенд вернётся на HTTP, заходившие пользователи не откроют его до истечения срока. Увеличиваем, когда HTTPS на стенде проработает без откатов. `includeSubDomains` и `preload` не ставим: у стенда IP, а не домен, и в список предзагрузки браузеров IP не попадает.

### Проверка после деплоя

Три проверки в отдельном шаге: HTTP/2 по TCP, `Alt-Svc` с `h3` на `/` и ответ по `--http3-only`. Для последней нужен curl с HTTP/3. На раннере его нет, в `curlimages/curl` и `alpine` тоже, а в `debian:trixie-slim` curl 8.14 собран с nghttp3. Проверка снаружи заодно подтверждает, что UDP 443 доходит до стенда через сеть провайдера. Сбой установки curl даёт своё сообщение, чтобы не искать проблему в сети.

### Проверка конфига в CI

Ошибка в конфиге nginx до сих пор всплывала только при деплое: контейнер не стартует, стенд недоступен. Job `nginx` в `ci.yml` собирает образ и в нём запускает скрипт выбора режима и `nginx -t` дважды — без `PUBLIC_HOST` (режим HTTP) и с ним (режим HTTPS из шаблона). Проверяется именно образ, а не файлы из репозитория: директивы `http3` и `add_header_inherit` зависят от версии nginx, `acme_*` — от подключённого модуля, а HTTPS-конфиг существует только после подстановки переменных.

Заглушки не нужны: сертификат приходит из `$acme_certificate`, адрес API — из `$api_upstream`, и `nginx -t` не ищет ни файлов сертификата, ни DNS. Поэтому контейнер запускается с `--network none`.

## Проверено

### Локальный стенд с заглушками

Docker, `nginx:1.30-alpine`, самоподписанный сертификат, заглушка SSE-эндпоинта по контракту из `review-run-live-status`, curl из `debian:trixie-slim` в той же docker-сети.

| Проверка                                      | Результат                                                                |
| --------------------------------------------- | ------------------------------------------------------------------------ |
| `nginx -V`                                    | `--with-http_v2_module`, `--with-http_v3_module`                         |
| запрос по TCP                                 | `HTTP/2 200`, `alt-svc: h3=":443"; ma=86400`                             |
| `--http3-only`                                | ответ по `HTTP/3.0`                                                      |
| `Alt-Svc` в `location` со своим `add_header`  | есть при `add_header_inherit merge`                                      |
| сертификат из переменной (как у ACME) по QUIC | работает                                                                 |
| SSE по HTTP/3 и HTTP/2                        | события доходят за 1–5 мс, поток закрывается после терминального статуса |
| 10 параллельных SSE                           | HTTP/1.1 — 10 соединений, HTTP/2 — 1, HTTP/3 — 1                         |
| UDP 443 закрыт                                | `--http3` откатывается на HTTP/2 за 7 мс                                 |

### Настоящий образ интерфейса

Образ из этой ветки, `site.conf` и статика — как на стенде. В боевом шаблоне ACME заменён файлами сертификата. По HTTP/1.1, HTTP/2 и HTTP/3 одинаково:

- `/`, `/index.html`, `/assets/*.js`, `/assets/*.css` отдаются с одинаковым содержимым (sha256 совпадает), `Cache-Control` у `index.html` и `/assets/` сохраняется, `Alt-Svc` есть в каждом ответе;
- SPA-маршрут (`/reviews/123`) отдаёт `index.html`;
- `/api/` проксируется на API, SSE через прокси `site.conf` доходит целиком;
- с `Accept-Encoding: gzip` JS приходит как 68 КБ вместо 220 КБ, после распаковки sha256 совпадает с исходным; без заголовка — исходный файл; `Vary: Accept-Encoding` есть;
- JSON API сжимается на лету;
- SSE с `Accept-Encoding: gzip` приходит без `Content-Encoding`, события — через 1–5 мс после отправки.

Логика шага проверки из `deploy.yml` прогнана против этого образа: на исправном стенде шаг зелёный, при закрытом UDP 443 и при сбое установки curl падает со своим сообщением.

Job `nginx` из `ci.yml` прогнан против этого образа: оба режима проходят без сети, а опечатка `http3 onn;` в шаблоне роняет проверку с указанием строки.

### Let's Encrypt и QUIC

Настоящий образ с боевым шаблоном против Pebble — тестового ACME-сервера Let's Encrypt — с профилем `shortlived` на 4 минуты. Отличие от стенда одно: `ssl_verify off` в `acme_issuer`, у Pebble тестовый корень.

- nginx сам прошёл проверку HTTP-01 на `:80` и получил сертификат;
- этот сертификат отдаётся и по HTTP/2, и по HTTP/3;
- до истечения модуль продлил сертификат, и новый сразу отдаётся по обоим протоколам — без перезапуска nginx.

### Сеть провайдера

UDP-проба на `62.169.24.237:443` и `:4433` получает ICMP «port unreachable» от хоста: UDP доходит до VPS, провайдер его не режет.

Не проверено: боевой Let's Encrypt с IP-сертификатом и браузер. Это закрывает проверка после деплоя и ручная проверка Protocol `h3` в DevTools.

## Risks / Trade-offs

- **UDP перестанет проходить** (смена провайдера, файрвол) → деплой упадёт на шаге HTTP/3. Пользователи при этом продолжат работать по HTTP/2. Выход — открыть UDP или временно убрать `listen … quic`.
- **QUIC дороже по CPU**: шифрование и обработка пакетов идут в user space. На нашей нагрузке это незаметно.
- **Шаг проверки зависит от `apt` в Debian** → около 20 секунд на деплой и внешний источник. Если начнёт мешать, можно собрать свой образ с curl.
- **Новый тип ответа API, которого нет в `gzip_types`**, уйдёт без сжатия — это безопасный отказ, а не поломка.
