## Context

Бэкенд оценивает состояние по сработавшим критическим алертам мониторинга и кэширует оценку
на 15 секунд. Ручка `GET /api/v1/status` открыта без сессии и отвечает `200` и тогда, когда
мониторинг лежит: компоненты тогда `unknown`. Общее состояние — худшее из компонентов в порядке
`outage`, `degraded`, `unknown`, `operational`. Компоненты всегда `api`, `worker`, `queue`.

Приложение под `/app/` закрыто для гостя в nginx; исключение уже есть у «Помощи»
(`location ~ ^/app/help/?$`).

## Decisions

- **Маршрут SPA вне `RequireAuth`, как «Помощь».** Исключение в nginx — та же регулярная
  location: `^/app/(help|status)/?$`. Глубже `/app/status/` гостя по-прежнему уводят на вход.
  `location /api/` cookie не проверяет, поэтому отдельного правила для ручки не нужно; с
  заглушкой API в той же сети проверено, что гость получает её ответ.
- **Опрос — `refetchInterval` TanStack Query, 30 секунд, и `refetchOnWindowFocus`.**
  `staleTime` 15 секунд — как кэш сервера: возврат на вкладку раньше ничего нового не принесёт.
  На скрытой вкладке интервал не тикает (по умолчанию TanStack Query). Повторов при ошибке
  нет (`retry: false`): опрос и так повторит запрос через 30 секунд. С общими повторами
  приложения (`shouldRetry`, ещё две попытки) зависший API держал бы на экране прошлое
  «Работает» около трёх минут — три запроса до таймаута nginx по 60 секунд. Предел остаётся:
  зависший запрос висит до этого таймаута, и до тех пор страница показывает прошлый ответ.
  Цена — единичный сбой сети перекрашивает страницу до следующего опроса.
- **Сбой запроса — тоже состояние сервиса, а не экран ошибки.** Пока API не ответил (сеть,
  `5xx`, `502` от nginx при лежащем контейнере API), API «Недоступен»; о воркере и очереди
  сообщает только API, поэтому про них «Нет данных». Если API ответил, но не так (`4xx`, ответ
  вне контракта), он работает, а состояние неизвестно: все три — «Нет данных». Время
  проверки — момент неудачного запроса. Сбой опроса после удачного ответа тоже показывает
  этот вид, а не последний удачный ответ: страница статуса не должна показывать «Работает»,
  когда API уже не отвечает.
- **Ответ сводится в вид страницы в сущности** (`viewFromReport`, `viewFromFailure`): чистые
  функции с unit-тестами, страница только рисует. Компоненты на странице всегда три и в
  порядке контракта; пропавший в ответе — «Нет данных».
- **Рост enum бэкенда не роняет страницу.** Незнакомое состояние zod читает как `unknown`
  (`.catch`), незнакомый компонент отбрасывается. Выводимый тип схемы при этом совпадает с
  контрактом — `MatchesContract` проверяет его при сборке.
- **Подписи и цвета.** Слова «Работает», «Работает со сбоями», «Недоступен», «Нет данных» —
  одни для общего состояния и компонентов. Компоненты называются для пользователя: «API»,
  «Обработка ревью», «Очередь задач». Цвет — тегами и `Alert` antd: тёмная тема
  перекрашивает их сама. Время — `formatDateTime` из `shared/lib`, один формат на приложение.
- **Общий каркас публичных страниц.** Шапка «Помощи» (название, «В кабинет», тема) переезжает
  в `widgets/app-shell` как `PublicLayout`; «Помощь» и «Статус сервиса» его используют.
