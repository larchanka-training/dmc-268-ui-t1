## Context

Мотивация — в `proposal.md`. Из кода приложения mock adapter собирает только `src/app/App.tsx`, а из тестов его используют `src/app/App.test.tsx` (маршруты, глубокие ссылки, сценарий живого прогона) и `sessionApi.test.ts` (профиль `MOCK_USER`). Остальные тесты уже работают на `fakeTransport`, `stubFetch` и `createFakeEventStream` из `src/test`. `shouldRetry` в `src/app/providers/queryClient.ts` не повторяет `4xx`, `501` и `ContractError`. `useReviewDiff` считает `404` и `501` «диффа нет» и отдаёт `null`; любая другая ошибка оставляет экран со списком замечаний без объяснения.

## Goals / Non-Goals

**Goals:**

- Один источник данных в приложении; тесты не зависят от удалённого кода.
- Причина отсутствия диффа видна пользователю; постоянная ошибка не перезапрашивается.

**Non-Goals:**

- Ручной запуск ревью (`POST /reviews`, api#273): в кабинете его нет, заглушка бэкенда на эту работу не влияет.
- Обработка `501` у настроек и статуса правил (`RepositorySettingsPage`): в контракте их больше нет, код остаётся безвредным и уходит отдельной задачей.
- Шаги прогона: поведение на `501` не меняется (снято в ui#125).

## Decisions

### Тесты — на фейке транспорта, а не на MSW

`fakeTransport`, `stubFetch` и `createFakeEventStream` уже есть в `src/test`, они типизированы по `ApiTransport` и `EventStream`, а фабрики из `src/test/factories.ts` дают модели по контракту. Тест сценария прогона толкает события потока руками вместо таймеров сценария — короче и без `vi.useFakeTimers`. TEST_PLAN уже требует «подменяется adapter, а не `fetch`».

Альтернатива — MSW с обработчиками по `schema.d.ts`: ближе к HTTP, но новая зависимость и вторая инфраструктура тестов при том, что остальные тесты остаются на фейках.

### Причина ошибки диффа — в `pages/review-run`

Сопоставление `code` → заголовок живёт в `pages/review-run/model` рядом с `useReviewDiff`: это решение экрана, а не сущности диффа. Текст — `detail` ответа (`ApiError.message`), как во всём кабинете. Показ — `ErrorState` из `shared/ui`, без `onRetry` у постоянных ошибок. Повторов не добавляем: `shouldRetry` уже не повторяет `4xx`, тесты это закрепляют.

### Тег образа — только sha

Источник данных больше не параметр сборки, суффикс ничего не различает. Развёртывание идёт по digest, поэтому смена формы тега на него не влияет.

## Risks / Trade-offs

- [Локальная разработка требует бэкенда и своей GitHub App] → README описывает `make run-local` и `docs/LOCAL_RUN.md` бэкенда; проксирование на стенд не работает (OAuth, cookie и `Origin` привязаны к домену стенда), это тоже в README.
- [Скриншоты лендинга `landing-page` 2.3 «с моков»] → снимаются со стенда или с локального бэкенда.
- [Дельты опираются на неархивированные `session-cookie` и `review-run-diff-viewer`] → архивировать этот change после них; порядок записан в PR.

## Migration Plan

После мёржа в `develop` удалить переменную репозитория `VITE_USE_MOCK_API` (`gh variable delete`). Откат — revert PR, но **перед ним** завести переменную снова: `gh variable set VITE_USE_MOCK_API --body false`. Старый `deploy.yml` читает `vars.VITE_USE_MOCK_API || 'true'`: без переменной revert соберёт стенд на моках.
